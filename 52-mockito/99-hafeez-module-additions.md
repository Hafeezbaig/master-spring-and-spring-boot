# 99 - Hafeez Module Additions (52-mockito)

**Module:** `52-mockito` (First 5 Steps in Mockito)

This is a Spring Boot project. The lecture teaches the Mockito basics over a
tiny `SomeBusinessImpl` / `DataService` pair. I kept every lecture file as it
is (the videos walk through them), fixed the one thing that printed a warning
on every test run, and added one file that shows the Mockito features a real
project uses next.

Versions (all from the Spring Boot parent, nothing pinned by hand):
Spring Boot **4.0.6**, Mockito **5.20.0**, JUnit Jupiter **6.x**. Java **17+**
(the pom asks for Java 25, which is what the course pom already used).

---

## 1. What changed, file by file

### New files

| File | Why |
|---|---|
| `src/test/java/com/in28minutes/mockito/mockitodemo/business/SomeBusinessImplMockitoFeaturesTest.java` | The Mockito features the 5-step lecture skips, over the course's own `SomeBusinessImpl` / `DataService`. Shows `verify` (`times`, `never`), `thenThrow`, BDD style (`given().willReturn()`, `then().should()`), `ArgumentCaptor` + `@Captor`, `@Spy` / `spy`, matchers `any` / `eq`, and an AssertJ example. One small test per feature. 8 tests. |
| `99-hafeez-module-additions.md` | This file. |

### Modified files

| File | What changed | Why |
|---|---|---|
| `pom.xml` | Added a Surefire `argLine` that loads Mockito as a Java agent at JVM start, and declared `mockito-core` (test scope, no version) so the agent path resolves. | Mockito printed "Mockito is currently self-attaching... this will no longer work in future releases of the JDK" on every run. Loading it as an agent removes the warning and keeps the build working on newer JDKs. `mockito-core` was already pulled in by the test starter, so this only makes it a direct dependency. |
| `readme.md` | Kept all the lecture text and the "Complete Code Example" code as they were. Added: **How to Run**, a note on the Mockito agent line, **Notes** (lecture-vs-new table, stubbing / verification / matcher / annotation cheat sheets, mock-vs-spy, style tips), **Useful References** doc links. | A clear run guide, doc links, and short cheat sheets. |
| `.gitignore` | Was just `*.idea`. Added `target/`, compiled classes, the usual IDE files, and `.DS_Store`. | So Maven build output and editor files stop showing up as git changes. |

### Unchanged files (left alone on purpose)

| File | Why |
|---|---|
| `src/main/.../MockitoDemoApplication.java` | Spring Boot entry point. No change needed. |
| `src/main/.../business/SomeBusinessImpl.java` (and the `DataService` interface in it) | Lecture code the videos reference by name. The new test reuses it as is. |
| `src/test/.../business/SomeBusinessImplStubTest.java` | Stub-vs-mock demo the lecture walks through. |
| `src/test/.../business/SomeBusinessImplMockTest.java` | The lecture's `@Mock` / `@InjectMocks` test. |
| `src/test/.../list/ListTest.java` | The lecture's "mock the List interface" demo. |
| `src/test/.../MockitoDemoApplicationTests.java` | Default Spring Boot context-load test. |
| `src/main/resources/application.properties` | Empty in the lecture. Left empty. |
| `HELP.md` | Generated by Spring Initializr. Left as is. |
